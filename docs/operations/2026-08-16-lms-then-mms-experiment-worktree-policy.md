# LMS→MMS 실험 worktree 운영 정책

작성일: 2026-08-16
상태: 적용

## 목적

기존 통합 MMS 운영 코드와 실험적인 LMS 선행·이미지 MMS 후행 구현을 물리적 작업 디렉터리와 Git 브랜치 수준에서 분리한다. 실험 결과는 별도 승격 결정 전까지 main 운영 상태에 영향을 주지 않는다.

## 작업 영역

| 구분 | 브랜치 | 작업 경로 | 책임 |
| --- | --- | --- | --- |
| 기존 운영 | `main` | `C:\workflows\send-mms-workflow` | 현재 통합 MMS 코드, 기존 운영 문서, 운영 hotfix |
| LMS→MMS 실험 | `experiment/lms-then-mms-worker-pipeline` | `C:\workflows\send-mms-workflow-lms-then-mms` | 실험 스펙, 구현 계획, 14열 결과 정책, 구현과 모의 테스트 |

각 worktree의 루트 `AGENTS.md`가 해당 작업 영역의 구현·검증 규칙을 정의한다. 실험용 `AGENTS.md`를 main에 복사하거나 main의 운영 규칙을 실험 구현에 맞춰 변경하지 않는다.

## 변경 방향

- 기존 운영 변경은 `main`에서 먼저 수행한 뒤 필요할 때 `main → experiment` 방향으로 반영한다.
- 실험 브랜치의 스펙, 계획, 코드와 결과 스키마는 일반 개발 과정에서 main으로 병합하지 않는다.
- `experiment → main` 반영은 별도의 승격 검토와 사용자의 명시적 승인 후에만 수행한다.
- 구현 계획은 실험 worktree 안에서만 작성하고 실행한다.

## 데이터와 실행 격리

- 실험 worktree에서는 실제 SENS 발송을 수행하지 않는다.
- main의 `.env`, 실제 `receiving_numbers.csv`, `mms_img`, `results`, `logs`를 실험 worktree로 복사, 이동, 링크 또는 공유하지 않는다.
- 실험 테스트는 가짜 자격증명, 비실제 번호, 생성된 테스트 이미지와 모의 transport만 사용한다.
- 실험 worktree의 출력과 테스트 임시 데이터는 main의 결과·로그 경로에 쓰지 않는다.
- worktree 생성, 구현, 테스트 또는 계획 승인은 실발송 승인으로 간주하지 않는다.

## 승격 조건

실험 구현을 main 후보로 검토하려면 다음 조건을 모두 충족해야 한다.

1. 최신 SENS 공식 API 계약을 다시 확인한다.
2. 전체 모의 테스트와 동시성·마이그레이션·개인정보 회귀 테스트가 통과한다.
3. 기존 통합 MMS 운영 흐름에 대한 영향과 롤백 절차를 별도로 검토한다.
4. 8열에서 14열로의 결과 마이그레이션을 복제 데이터로 리허설한다.
5. 사용자에게 변경 범위와 검증 결과를 제시하고 별도의 승격 승인을 받는다.

승격 승인은 실제 LMS/MMS 발송 승인이 아니다. 실발송에는 실행 직전의 별도 명시적 승인이 필요하다.

## 보존과 정리

- 실험 브랜치와 worktree는 사용자의 별도 지시 없이 삭제하지 않는다.
- 실험 로그, 결과 또는 스냅샷이 생성되더라도 자동 삭제하지 않는다.
- 실험 중단 시에도 main의 기존 운영 코드와 결과 파일을 변경하거나 초기화하지 않는다.
